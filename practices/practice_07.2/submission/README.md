# Защита практики 7.2: Workflow 1

Откройте [index.html](index.html) в браузере. Презентация содержит 18 слайдов и покрывает часть 1: классификацию, эскалацию и вынос классификатора в Sub-workflow.

## Управление

- Стрелки ← / →, PageUp / PageDown и пробел переключают слайды.
- Home / End открывают первый / последний слайд.
- F или кнопка «Полный экран» включает полноэкранный режим.
- N или «Заметки» показывает подсказки докладчику. В печать они не попадают.
- Нажатие на скриншот открывает исходное изображение в новой вкладке.
- «Печать / PDF» печатает все слайды в A4 landscape. В диалоге браузера отключите колонтитулы и включите печать фона.

Презентация работает локально без внешних библиотек и CDN. Для ссылок на GitHub нужен интернет. При передаче сохраните всю папку submission: HTML, assets и workflow_1.

## Порядок слайдов

1. Титульный слайд.
2. Три критерия части 1, суммарно 5 баллов по заданию.
3. GitHub Trigger, фильтр opened и подготовка контекста.
4. Basic LLM Chain, модель, промпт и контракт parser.
5. Порог 0.8 и Build Route.
6–9. Запуски до переноса: bug, task, feature, unknown с confidence 0.35.
10. Разделение основного workflow и классификатора, входы и выходы.
11. Схема дочернего классификатора из subworkflow.png.
12–15. Запуски после переноса: bug, task, feature, unknown с confidence 0.3.
16. HTTP-запросы установки labels.
17. Ссылки на локальные экспорты и тестовый репозиторий.
18. Порядок живой демонстрации.

## Материалы и границы подтверждений

Контент основан на исходных [01_issue_intake.json](workflow_1/01_issue_intake.json), [02_classify_issue.json](workflow_1/02_classify_issue.json) и восьми скриншотах запусков в beforeSubWorkFlow / afterSubWorkFlow. Дополнительно включена схема дочернего сценария subworkflow.png. Изображения и JSON сохранены без изменений. Значения 0.35 и 0.3 читаются на скриншотах unknown. Значения confidence для остальных запусков не придуманы и в презентации не указаны.

В комплекте пока нет отдельных скриншотов страниц GitHub Issues и деталей дочернего Execution. На защите нужно открыть реальные Issues с labels, показать отсутствие комментария у needs-triage и открыть вход/выход дочернего запуска в n8n. На слайдах стоят ссылки на выборки Issues по label, номера конкретных Issues не выдуманы.

В экспортированном If включена loose type validation и после выражения есть перенос строки. Презентация описывает фактический фильтр и не утверждает, что он настроен в строгом режиме. При импорте workflow подключите свои credentials и проверьте ссылку Call classifier на дочерний workflow.
