# Защита практики 7.2: Issues и недельная статистика

Откройте [index.html](index.html) в браузере. Презентация содержит 29 слайдов: часть 1, недельную статистику и задание со звёздочкой. Слайды показывают фактическую реализацию и отдельно обозначают отличия от критериев.

## Управление

- Стрелки ← / →, PageUp / PageDown и пробел переключают слайды.
- Home / End открывают первый / последний слайд.
- F или кнопка «Полный экран» включает полноэкранный режим.
- N или «Заметки» показывает подсказки докладчику. В печать они не попадают.
- Нажатие на скриншот открывает исходное изображение в новой вкладке.
- «Печать / PDF» печатает все слайды в A4 landscape. В диалоге браузера отключите колонтитулы и включите печать фона.

Презентация работает локально без внешних библиотек и CDN. Для ссылок на GitHub нужен интернет. При передаче сохраните всю папку submission: HTML, assets, workflow_1 и weekStatistics.

## Материалы и границы подтверждений

Контент основан на исходных [01_issue_intake.json](workflow_1/01_issue_intake.json), [02_classify_issue.json](workflow_1/02_classify_issue.json) и восьми скриншотах запусков в beforeSubWorkFlow / afterSubWorkFlow. Дополнительно включена схема дочернего сценария subworkflow.png. Изображения и JSON сохранены без изменений. Значения 0.35 и 0.3 читаются на скриншотах unknown. Значения confidence для остальных запусков не придуманы и в презентации не указаны.

В комплекте пока нет отдельных скриншотов страниц GitHub Issues и деталей дочернего Execution. На защите нужно открыть реальные Issues с labels, показать отсутствие комментария у needs-triage и открыть вход/выход дочернего запуска в n8n. На слайдах стоят ссылки на выборки Issues по label, номера конкретных Issues не выдуманы.

В экспортированном If включена loose type validation и после выражения есть перенос строки. Презентация описывает фактический фильтр и не утверждает, что он настроен в строгом режиме. При импорте workflow подключите свои credentials и проверьте ссылку Call classifier на дочерний workflow.

## Недельная статистика: подтверждения и отличия

Включены все семь оригинальных изображений из `weekStatistics/`. Числа перенесены с них: bug = 3, task = 2, feature = 2, needs-triage = 3, total = 10, автор ramilEmazanov. Письмо сравнивает их с симулированной неделей total = 6 и показывает Δ +4. Период 16–22 ноября на момент ручного запуска 20 ноября не завершён, что указано на слайде и в AI-комментарии.

Полученное письмо отправлено **Send Email через SMTP обычным текстом**. Критерий 6 требует **Gmail node и HTML-письмо с таблицей**. Презентация показывает отправку и доставку, но не выдаёт их за буквальное выполнение этого критерия. По README практики оценивание последовательное, поэтому зачёт этой замены влияет и на следующие критерии.

Что нужно открыть вживую или добавить в материалы:

- Период из Prepare Period и настройки timezone Europe/Moscow.
- Параметры и результаты Fetch Task, Fetch Feature, Fetch Triage. Отдельный снимок ответа имеется только для bug.
- total и snapshot_json двух корректных строк Data Table, выполнение Save Week, Get Previous Week и Compute Delta.
- Вход и выход Basic LLM Chain. В письме виден результат, общая схема показывает выполнение цепочки.
- Экспорт временного Seed, если он используется. Экспорт основного отчёта уже включён: [03_weekly_report.json](weekStatistics/03_weekly_report.json); в презентации есть ссылки на GitHub и локальную копию.

На скриншоте Data Table строка ID 1 содержит Null: это историческая ошибочная запись. Две строки с заполненными ключами относятся к 9 и 16 ноября. Исходный скриншот сохранён без ретуши.
