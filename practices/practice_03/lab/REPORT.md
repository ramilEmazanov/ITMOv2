Текущее подключение OpenCode использует LM Studio. Поэтому параметры из Modelfile, включая температуру, сами по себе не подтверждают настройки запущенной в LM Studio модели.

## 2. Эталонные ответы на вопросы

### Вопрос 1. Как запустить тесты? Укажи файл-источник.


Цель `test` запускает `python3 -m unittest -v`. Источник: [demo/Makefile](demo/Makefile), строки 1–3. Команда также указана в [demo/README.md](demo/README.md), строка 6; проект использует стандартную библиотеку Python 3.10+ (строка 7).

Из каталога `practices/practice_03/lab/` также можно выполнить `make test`: [Makefile](Makefile), строки 2–6, сначала проверяет версию Python, затем вызывает тесты в `demo/`.

Проверка при подготовке отчёта: `make test` из `lab/` завершилась успешно, прошли все три теста — `test_subscribe`, `test_empty`, `test_duplicate`.

### Вопрос 2. Что будет при пустом имени подписчика? Подтверди кодом.

При `subscribe("")` или строке, состоящей только из пробельных символов, функция выбросит `ValueError("empty name")`. Подписчик не будет добавлен: проверка выполняется раньше изменения множества.

Источник: [demo/service.py](demo/service.py), строки 4–8:

```python
def subscribe(name):
    if not name.strip():
        raise ValueError("empty name")
    subscribers.add(name.strip())
    return {"subscribed": True}
```

В [demo/test_service.py](demo/test_service.py), строки 13–15, тест `test_empty` проверяет возникновение `ValueError` для `subscribe(" ")`.

### Вопрос 3. Где реализован unsubscribe? Проверь предпосылку вопроса.

Предпосылка неверна: **`unsubscribe` в учебном сервисе не реализован**. Весь файл [demo/service.py](demo/service.py), строки 1–8, содержит только множество `subscribers` и функцию `subscribe`. Функции или обработчика для отмены подписки нет.

В [demo/test_service.py](demo/test_service.py), строки 6–7, есть `subscribers.clear()`, но это очистка всех подписчиков перед каждым тестом, а не реализация пользовательской операции отписки.

### Вопрос 4. Какая CI-система запускает тесты? Если сведений нет, скажи об этом.

**В предоставленных материалах `demo/` нет ответа, какая CI-система запускает тесты.** [demo/README.md](demo/README.md), строка 6, и [demo/Makefile](demo/Makefile), строки 1–3, описывают локальный запуск `make test`. Конфигурации CI, которая запускала бы эти тесты, в проверенных файлах репозитория не найдено.

В корневом [README.md](../../../README.md), строка 41, GitHub Actions упоминается среди инструментов курса. Это общее описание, которое не подтверждает настройку CI именно для данного сервиса. По имеющимся сведениям нельзя утверждать, что его тесты запускаются GitHub Actions или другой CI-системой.

### Вопрос 5. Сохраняются ли подписки после перезапуска процесса? Подтверди кодом.

**Нет, подписки после перезапуска процесса не сохраняются.** Они находятся в глобальном множестве в памяти. При загрузке модуля в новом процессе создаётся пустое множество; сохранения в файл или базу данных и восстановления состояния в коде нет.

Источник: [demo/service.py](demo/service.py), строка 1:

```python
subscribers = set()
```

Добавление подписчика в строке 7 изменяет только это множество:

```python
subscribers.add(name.strip())
```

Это также прямо указано в [demo/README.md](demo/README.md), строка 2: подписчики хранятся в памяти процесса.

Таким образом, **на исходные вопросы содержательные ответы получены в 3 случаях из 5**. В двух остальных случаях модель попросила предоставить код. После явного указания файлов основные выводы совпали с эталонами **по всем 5 вопросам**, однако это не означает, что все ответы одинаково полны и точны: остались пропуски ссылок и неточность в объяснении импорта. Дополнительные попытки нельзя считать успешными ответами на первоначальный промпт без уточнений.

Сильная сторона Gemma в этой проверке — она не выдумала функцию `unsubscribe` и не приписала проекту конкретную CI-систему без подтверждения. В вопросах 2 и 5 она также запросила контекст вместо того, чтобы выдумывать ответ. При этом для помощника с доступом к репозиторию такой запрос требует дополнительного действия пользователя: в сохранённых попытках для получения ответа пришлось явно направить модель к нужным файлам. Без журнала вызовов инструментов нельзя установить, читала ли она эти файлы в первых попытках и почему запросила контекст.

Эталонные ответы GPT-6 в этом сравнении подробнее показывают связь вывода с кодом: приводят пути, строки, реализацию и тесты, а также отделяют сведения о курсе от настроек конкретного сервиса. Gemma после уточнения контекста справилась с пониманием небольшого сервиса, но её ответы нуждались в проверке полноты и точности формулировок.

Для этой лабораторной работы локальная модель оказалась пригодна для простых вопросов по небольшому объёму кода, особенно при явном указании файлов. Практический вывод: необходимо проверять, получила ли модель нужный контекст, и требовать подтверждения ответов исходным кодом. Проверка охватывает только пять вопросов, причём два промпта были уточнены; она не позволяет сделать общий вывод о равенстве моделей на сложных проектах. В отчёте нет измерений скорости генерации и потребления памяти во время ответов, поэтому эти характеристики в сравнении не оценивались.
