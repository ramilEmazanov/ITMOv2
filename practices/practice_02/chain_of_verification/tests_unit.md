## Вопросы проверки

Вопросы сформулированы до поиска evidence. Для каждого требования проверяются четыре условия:

1. Есть ли реализация компонента и исполняемый unit-тест?
2. Проверяет ли тест результат содержательным `assert`?
3. Изолирован ли внешний LLM через mock/fake, исключены ли сетевые вызовы?
4. Воспроизводится ли запуск командой `pytest -q tests/unit` из корня репозитория?

| Требование | Предмет этих четырёх вопросов |
|---|---|
| SEC-1 | Удаление секретов до передачи diff во внешний LLM, сохранение безопасного текста |
| REL-1 | Timeout 10 секунд и контролируемый ответ при ошибке LLM |
| OUT-1 | Поля summary, risks, checks, максимум три риска и обязательные поля каждого риска |
| QA-1 | Подтверждение каждого риска строкой diff или правилом; одного заполненного evidence недостаточно |
| OBS-1 | Только request_id, длительность и статус в логах, отсутствие diff и ответа модели |

CASE.md не задаёт точную схему контролируемой ошибки, типы всех полей, политику пустых значений и выбор между отклонением, фильтрацией и нормализацией невалидного ответа. Эти решения нужно определить перед написанием соответствующих assert; сейчас подтверждены только ограничения из правил. Обрезание до трёх рисков не заменяет проверку доказательности QA-1.

## Воспроизводимость и оставшиеся ограничения

- Планируемая команда после появления реализации, тестов и зависимостей: `pytest -q tests/unit` из корня репозитория.
- В этой проверке команда **не запускалась**, поскольку реализации и тестов нет; кода завершения unit-запуска нет. Выполнен только поиск `command -v pytest`: пустой вывод, код 1, команда не найдена в текущем PATH. Это не утверждение об отсутствии pytest во всех возможных окружениях.
- Исполняемых unit-тестов, assert и mock/fake не найдено; ничего из этого не создавалось. Учебный diff не применялся как реализация.
- После реализации запуск должен использовать только синтетические данные, внедрённый fake/mock LLM, запрет исходящей сети и управляемые часы. Изоляцию ещё предстоит подтвердить по тестовому коду и запуску.
- Пока нельзя подтвердить поведение компонентов по всем пяти требованиям, покрытие границ, отсутствие утечек в prompt/логи и успешность unit-тестов. Подтверждены лишь содержимое учебного примера, отсутствие исполняемого кода/тестов и характер проверок в Makefile.

## Как использовали AI

- Вопросы сформулированы до проверки; evidence найден отдельно. Имена планируемых тестов удалены из evidence, сценарии уточнены, фактические ограничения отделены от ожидаемых проверок.
- Успешный запуск, наличие assert и изоляция LLM не заявляются без исполняемых тестов.
