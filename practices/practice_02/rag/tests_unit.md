## Условия unit-проверок

Все секреты и ответы ниже синтетические. LLM заменяется fake/spy, сеть не вызывается. Очистка, валидация, проверка доказательств и логирование рассматриваются как отдельные обязанности; наличие соответствующих функций в коде не предполагается. Для timeout нужен spy настройки внешнего адаптера и управляемый fake, без реального ожидания 10 секунд.

Обозначения входов:

- `D_safe = "+value = 1\n"`, `D_empty = ""`; `\n` в строковых литералах означает перевод строки.
- `D_secrets = "+TOKEN=test-token\n+password=test-password\n+value = 1\n"`.
- `D_key = "+-----BEGIN PRIVATE KEY-----\n+SYNTHETIC-KEY-NOT-REAL\n+-----END PRIVATE KEY-----\n+value = 1\n"` — фиктивный блок, не действующий ключ.
- `V(rs) = {"summary": "Синтетический обзор", "risks": rs, "checks": ["Проверить контракт"]}`; `V([])` также проверяется с `checks=[]`.
- `D_review` — синтетический diff ниже, воспроизводящий операции из [строк 20–22 учебного diff](../../practice_01/TRAINING_PR.diff#L20). Только в этой фикстуре новые строки файла имеют номера 1, 2, 3.

```diff
diff --git a/app/review_service.py b/app/review_service.py
--- a/app/review_service.py
+++ b/app/review_service.py
@@ -0,0 +1,3 @@
+prompt = f"Review this pull request and find problems:\n{diff}"
+answer = self.llm.generate(prompt)
+return {"comment": answer}
```

Для `D_review` заданы три корректных риска:

- `R1 = {"file": "app/review_service.py", "line": 1, "evidence": "prompt = f\"Review this pull request and find problems:\\n{diff}\"", "risk": "Исходный diff включается в prompt без удаления секретов (SEC-1)"}`.
- `R2 = {"file": "app/review_service.py", "line": 2, "evidence": "answer = self.llm.generate(prompt)", "risk": "Исключение generate не перехватывается (REL-1)"}`.
- `R3 = {"file": "app/review_service.py", "line": 3, "evidence": "return {\"comment\": answer}", "risk": "Ответ не содержит обязательные поля OUT-1"}`.

`V(...)` — вход валидатора; при проверке `review` fake LLM возвращает JSON-текст такого объекта, поскольку `generate` объявлен возвращающим `str`. JSON здесь — формат фикстуры, а не дополнительное требование к протоколу LLM. Захват логов охватывает все записи и дополнительные поля, а не только текст сообщения.

Ни одна проверка не запускалась. Статусы ниже отражают только сопоставление с diff: «дефект виден» — нарушение непосредственно следует из показанного кода; «не показано» — нужная реализация или наблюдение отсутствует в источниках. Ожидаемые результаты описывают требования, а не утверждают, что они уже выполнены. Формат контролируемой ошибки, HTTP-код, типы `summary`/`line` и стратегия обработки некорректного ответа источниками не определены. Отбрасывание лишних и недоказанных рисков взято из исходного плана; порядок выбора рисков не задан.

## Чего не хватало и какие сценарии добавлены

- Ссылок на правила и конкретные строки diff, а также честного статуса: названия планируемых тестов не доказывают их выполнение.
- SEC-1: проверки фактически отправленного prompt, нескольких и повторных секретов, пустого входа редактора.
- REL-1: отдельных сценариев для timeout и иной ошибки; наблюдаемой настройки ограничения ровно 10 секунд.
- OUT-1: отдельных границ 0, 1, 3 и 4 риска; пропущенных полей, неверных типов массивов и элементов, пустого/неструктурированного ответа; проверки контракта на выходе самого сервиса.
- QA-1: пустого и фиктивного evidence, цитаты, не подтверждающей вывод, подтверждения правилом, смешанного набора и отсутствия доказанных рисков.
- OBS-1: сценариев ошибки и timeout, проверки дополнительных полей логов, длительности на управляемых часах и утечки через сообщение исключения.

Планируемый запуск после появления реализации и тестов: `pytest -q tests/unit` ([исходный план, строка 14](../../practice_01/tests_unit.md#L14)). Этот документ — план проверок, а не отчёт о выполнении pytest.
