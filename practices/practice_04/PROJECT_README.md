# Проект: поиск недорогих авиабилетов

Веб-приложение ищет авиабилеты на конкретные даты и сравнивает минимальную найденную цену с предыдущим поиском по тем же параметрам. Фича **A** — поиск через Ignav, фича **B** — локальная история и сравнение. В [AGENTS.md](AGENTS.md) записаны правила для агента, а критерии практики — в [README.md](README.md).

## Как работает поиск (фича A)

Фронтенд на React, TypeScript и Vite принимает IATA-коды отправления и назначения, дату вылета, тип поездки и, для обратного рейса, дату возвращения. Можно выбрать прямые рейсы, максимальную цену и рынок (`RU`, `US`, `GB`, `TR` или `AE`). Рынок влияет на валюту: интерфейс показывает валюту, полученную в `price.currency`, без самостоятельного пересчёта.

По кнопке «Найти билеты» фронтенд отправляет `POST /api/fares/one-way` или `POST /api/fares/round-trip` в FastAPI. Бэкенд проверяет трёхбуквенные коды, полные даты `YYYY-MM-DD`, различие пунктов маршрута, порядок дат и положительный бюджет. Затем он обращается к [Ignav Flight API](https://ignav.com/docs/api-reference) с серверным ключом `IGNAV_API_KEY`. Для прямых рейсов передаёт `max_stops: 0`, для бюджета — `max_price` в валюте выбранного `market`. Ключ не попадает в браузер. Поддержка конкретного IATA-кода окончательно проверяется ответом Ignav.

Ответ Ignav нормализуется в `itineraries`: сохраняются `ignav_id`, цена, валюта, плечи и сегменты, пересадки считаются по числу сегментов. Карточки сортируются по цене. Пустой список показывает сообщение об отсутствии вариантов. Ошибки ввода, конфигурации и сервиса отображаются отдельно. Сетевые сбои и временную ошибку Ignav сервер повторяет ограниченное число раз; одинаковые успешные поиски кешируются на три минуты. Ссылка на бронирование не запрашивается, поэтому цены показываются как ориентировочные. Поиск запускается только кнопкой, а не при изменении полей. См. [поиск в одну сторону](https://ignav.com/docs/one-way), [туда-обратно](https://ignav.com/docs/round-trip), [ошибки](https://ignav.com/docs/errors) и [рекомендации по эксплуатации](https://ignav.com/docs/production-checklist).

Ignav ищет на конкретный день. Поиск минимума за весь месяц, подсказки аэропортов через `/api/airports` и ссылки на бронирование сейчас не реализованы.

## Как работает история (фича B)

После каждого успешного ответа FastAPI записывает время, нормализованные параметры поиска, валюту и минимальную цену в локальную SQLite-базу `backend/price_history.sqlite3`. Пустой ответ записывается без цены и не становится числовой точкой сравнения. Файл базы исключён из Git.

Сопоставляются только одинаковые маршрут, даты, тип поездки, рынок и фильтры. API возвращает `comparison` вместе с билетами: текущую и предыдущую минимальные цены, знаковую разницу и процент. Если прежней цены нет, возвращается `no_previous_price`; для пустого текущего ответа — `no_current_price`. Если при тех же параметрах Ignav вернул другую валюту, возвращается `currency_mismatch` без числовой разницы. Если прежняя цена равна нулю, процент не вычисляется. Общий расчёт расположен в `backend/app/price_math.py` и используется также MCP tool.

Повторный поиск в течение трёх минут сохраняется в историю, но может получить тот же тариф из кеша. Поэтому для проверки изменения цены используются подменённые ответы Ignav и временная база, без платного сетевого поиска. История не привязана к аккаунтам и не синхронизируется.

## Локальный запуск

Из корня репозитория в первом терминале:

```bash
cd practices/practice_04/backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
# Создайте backend/.env со строкой IGNAV_API_KEY=ваш_ключ; файл исключён из Git.
.venv/bin/uvicorn app.main:app --reload
```

Бэкенд читает ключ из переменной окружения `IGNAV_API_KEY` или локального `backend/.env`. Во втором терминале:

```bash
cd practices/practice_04/frontend
npm install
npm run dev
```

Откройте адрес Vite (обычно `http://localhost:5173`). Vite перенаправляет `/api` на FastAPI по адресу `127.0.0.1:8000`; доступен также `GET /health`. Живой успешный запрос к Ignav может тарифицироваться.

## Skill, MCP и автоматическая проверка

Локальный skill [`verify-flight-features`](.agents/skills/verify-flight-features/SKILL.md) запускает тесты FastAPI, тест hook, сборку фронтенда и офлайн-сценарий A → B с подменённым Ignav и временной SQLite. Из `practices/practice_04` его runner запускается так:

```bash
backend/.venv/bin/python .agents/skills/verify-flight-features/scripts/run.py --report verification/flight-features.md
```

В `opencode.json` подключены два MCP-сервера. Удалённый `context7` помогает агенту искать документацию библиотек; подтверждения вызовов лежат в `verification/context7-call.json` и `verification/context7-docs.json`. Локальный `flight-history` предоставляет `compare_prices`: он **только читает** сохранённую историю и не обращается к Ignav. Запуск, аргументы, ошибки и повторяемое демо настоящих MCP-вызовов описаны в [MCP_README.md](MCP_README.md); протокол — `verification/mcp-calls.json`.

Плагин OpenCode `.opencode/plugins/verify-after-edit.js` после правки кода через `edit`, `write`, `apply_patch` или `multiedit` запускает runner skill и добавляет результат `PASS`/`FAIL` в ответ инструмента агенту. Отчёт сохраняется в `verification/after-edit.md`. Изменения через shell и внешний редактор этот hook не видит. Тест hook запускается командой `node --test scripts/tests/verify-after-edit.test.mjs`; `node scripts/demo-after-edit.mjs` выполняет демонстрацию с временным файлом и сохраняет ответ в `verification/after-edit-hook.json`. Демо вызывает контракт hook самостоятельно; работу внутри OpenCode нужно показать отдельно после перезапуска OpenCode из `practices/practice_04`.

Git-хук `.githooks/pre-commit` дополнительно запускает `npm run build`, когда в коммит добавлены файлы фронтенда. В новом клоне включите его из корня репозитория через `git config core.hooksPath .githooks`.

Для [сдачи практики](README.md) остаётся собственный `reflection.md` с конкретными наблюдениями студента. Файлы конфигурации и сохранённые отчёты помогают демонстрации, но ревьюверу нужно показать применение инструментов и результат проверок.
